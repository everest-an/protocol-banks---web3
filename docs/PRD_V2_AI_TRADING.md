> 版本：v0.1 草案（待 P0 审计结果回填）
> 状态：骨架阶段 — 删除清单、Business 整合方案、账户模型细节待审计确认

## 1. 产品定位

**一句话**：连接钱包，AI 替你交易，随时提取利润。

面向普通加密用户的 AI 自动交易产品。用户用 MetaMask 连接，把愿意承担风险的资金放进交易子账户，云端 AI Agent 使用经过验证的策略自动交易，用户随时看收益、提取利润、一键叫停。企业支付功能降级为 Business 模块，不再主推。

**核心价值主张**：不懂交易的人，也能让专业级 AI 策略为自己工作。

## 2. 核心设计原则（不可妥协）

1. **易上手优先于功能全**：用户从进来到 AI 开始交易 ≤3 分钟，≤3 个动作。零配置默认值。
2. **一个屏幕 = 全部**：登录落地页即 AI 交易驾驶舱，不需要其他页面也能完整使用核心功能。
3. **AI 说人话**：所有 AI 活动以自然语言呈现（做了什么、为什么、赚/亏多少），无原始日志。
4. **风险透明**：用户永远知道自己最多亏多少（= 交易子账户余额），无隐藏敞口。
5. **非托管底线**：资金在用户自己的账户结构内，AI 无提现权限，用户可随时撤销/叫停。
6. **每个保留功能做到顺手**：半成品和孤儿代码整体删除，不留"能用但难用"的功能。
7. **用户隔离是硬约束**：所有交易数据、账户、密钥按用户严格隔离，绝不混用。

## 3. 目标用户

- 持有 USDC/ETH、想参与交易但不懂策略的加密用户
- 被"AI 代理交易"叙事吸引的 Web3 原生用户
- 有一定风险承受能力（能理解"可能亏光交易钱包"）

**非目标**：机构、企业支付客户（降级至 Business）、高频专业交易员（可用但非目标）。

## 4. 核心循环（v1 唯一必须做好的循环）

```
① 连接 MetaMask（SIWE 登录）
② 充值到交易子账户（设预算，默认 $100–500）
③ AI 开始交易（默认稳健策略，可选实验策略）
④ 驾驶舱实时观察：余额 / 收益曲线 / AI 活动流 / 持仓
⑤ 一键提取利润 → 回到主钱包
⑥ 随时可：暂停 AI / 清仓 / 撤销授权（kill switch）
```

**新手路径**：Paper trading 模式（模拟资金）→ 观察 ≥1 周 → 投真钱。

## 7. 交易驾驶舱规格（v1）

基于现有 vendors 页设计语言（玻璃卡片 / badge / 表格 / 网络图）改造：

```
┌────────────────────────────────────────────────┐
│  总资产  $520.40     今日 PnL  +$12.3 (+2.4%)  │  ← 玻璃卡片组
│  主钱包 $120  │  交易子账户 $400  │  [提取利润]  │
├────────────────────────────────────────────────┤
│  收益曲线（累计 + 日收益，可切 1D/7D/30D/ALL）    │  ← 主视觉
├──────────────────────────┬─────────────────────┤
│  AI 实时活动流            │  当前持仓（表格/badge） │
│  "10:32 加仓 BTC 多单    │  BTC  +2.3%  ETH ... │
│   （动量信号 0.87）"       │  [AI 状态: 运行中 ●] │
│  "10:15 平仓 ETH +$8.4"  │  [暂停] [紧急停止]   │
└──────────────────────────┴─────────────────────┘
```

- **AI 活动流**：自然语言，每条带时间、动作、理由、PnL，可点击看链上/交易详情
- **收益曲线**：用户最关心的东西放最大
- **提取利润**：一键 pull 子账户可用利润到主钱包（可选自动规则：日收益 > X% 自动提取）
- **风控永远可见**：最大亏损 = 交易子账户余额，写死在这个屏上
- **新手引导**：首次进入 3 步引导（连接 → 充值 → 启动）

## 8. 钱包架构（已核实 Hyperliquid 官方文档 2026-03）

### 8.1 已验证的账户模型事实

| 概念 | 事实 | 来源 |
|---|---|---|
| API 钱包（agent wallet） | 可代表账户操作，**无提现权限**；主账户 3 个、每子账户 +2 个；可设 `valid_until` 过期（最长 180 天） | 官方 docs + app.hyperliquid.xyz/API |
| 子账户（sub-account） | **需 $100,000 交易量解锁**（最多 10 个，每 +$1 亿量 +1 个）；无独立私钥，由主账户签名 + `vault_address` 指向子账户 | 官方 docs trading/sub-accounts |
| 资金转移 | `sub_account_transfer(subAccountUser, is_deposit, usd)` — `is_deposit=False` 即"提取利润回主账户" | Python SDK |
| SDK | `create_sub_account(name)` / `query_sub_accounts(address)` / `sub_account_transfer(...)` | hyperliquid-python-sdk |

### 8.2 ⚠️ 关键限制：子账户有 $10 万交易量门槛

用户想要的"交易钱包 + 不可移动主钱包"硬分离，在 Hyperliquid 上**只有子账户能做到**，但**新用户（<$10 万交易量）无法创建子账户**。因此零售 v1 必须用替代方案。

### 8.3 三个可选架构

> ✅ **已锁定：方案 A（API 钱包 + 平台风控），B 作为大额用户自动升级路径，C 弃用。**

| 已定决策 | 值 |
|---|---|
| 市场 | Hyperliquid 单市场优先 |
| 钱包架构 | 方案 A：API 钱包（agent，无提现权限）+ 平台风控层 |
| 策略 | 两条腿：80% 稳健 + 20% 因子挖掘实验仓 |

| 方案 | 资金分离 | 非托管 | 门槛 | 适用 |
|---|---|---|---|---|
| **A. API 钱包直接作用在主账户** | ❌ 软分离（AI 可动全部权益，预算靠平台风控强制） | ✅ 用户持私钥 | 无 | v1 零售默认 |
| **B. 子账户 + 子账户专属 API 钱包** | ✅ 硬分离（AI 只动子账户） | ✅ | $10 万交易量 | 活跃/大额用户升级路径 |
| **C. 平台代管独立"交易钱包"地址** | ✅ 硬分离（用户主钱包 AI 碰不到） | ⚠️ 交易钱包托管（平台持钥） | 无 | 若硬分离是零售刚需 |

- **方案 A（推荐 v1）**：最易上手。安全底线 = AI 无提现权限（链上保证，偷不走钱）+ 平台风控层（预算、每日亏损熔断、一键撤销 API 钱包）。
- **方案 B**：用户跨过 $10 万量后自动升级到硬分离，两钱包体验与用户设想完全一致。
- **方案 C**：最贴合"两个钱包"的直觉，但交易钱包变托管，需额外安全审计。

### 8.4 安全与护栏（三种方案通用）

- 利润提取：A = 用户自行提现；B/C = `sub_account_transfer(is_deposit=False)` 或链上 USDC 转回主钱包
- Kill switch = 撤销 agent/API 钱包权限 + 停止 agent 循环（双保险）
- agent 签名密钥：云端 Vault 加密，每用户独立，可随时撤销

## 9. 策略 v1（两条腿）

| 腿 | 仓位 | 策略 |

- Paper trading 一周起，再开放实盘
- 实验腿默认关闭，用户主动开启

## 10. 用户隔离（硬约束）

- DB：每用户独立数据行，RLS 或显式 userId 作用域（审计确认现状）
- 密钥：每用户独立 agent 密钥，Vault 存储，服务端不共享
- 账户：每用户独立 Hyperliquid 子账户，永不混用资金
- 日志：审计日志含 userId，可追溯每一笔 AI 决策
